## 1. Outcome

Three independent parallel investigation lenses covered the charter named by
Prompt 381 §20/§24 and `HARDENING_MATRIX.md` §12's own seeded punch list:
(Lens 1) browser/device environment feasibility; (Lens 2) a source-level static
evidence sweep (responsive breakpoints, table overflow, touch-target sizing,
upload/download/signed-URL Safari behavior, PWA scaffolding, modal dead-action
risk); (Lens 3) live testing at mobile/tablet viewports against the real
production build.

**Zero real device-compatibility defects found live** — 16/16 route×device
combinations (login, vendor-intake form, Supreme Admin guard redirect,
Procurement guard fail-safe × iPhone 13/Pixel 5/iPad Pro 11/375×667) rendered
with zero horizontal overflow, no obscured controls, no mobile-specific console
errors; mobile tap-to-submit resolved in 50ms with no hang, confirming
`HDN-380`'s dev-mode-hydration-race fix holds on a touch-emulated context too.

**5 real, static gaps found and fixed this checkpoint:**

- **Touch-target sizing** — `Button` (used in 218 real files, broad impact),
  `IconButton`, and the shared `Checkbox` all rendered under the commonly-cited
  44×44px touch-target guidance (`Button`/`IconButton` ~36px, the `Checkbox`
  row's own clickable area ~20px tall). Fixed with a `min-h-11`/`h-11 w-11`
  floor on each — a floor, not a forced height, so larger content still grows
  past it rather than being clipped.
- **`ToastProvider`'s viewport narrow-screen clipping** — a bare `w-80` (320px)
  plus its own `right-4` (16px) offset needs 336px of width; overflows past the
  left edge on any viewport ≤336px. Fixed with `max-w-[calc(100vw-2rem)]`.
- **4 files with the worst unwrapped tables** (of 23 originally found with zero
  overflow handling) wrapped in the same `overflow-x-auto` + `min-w-[Npx]`
  pattern the other 73 already use: `procurement/compliance/compliance-matrix-
  panel.tsx` (7 columns, the clearest live degradation case),
  `finance/dashboard/page.tsx` (3 tables), `commercial/dashboard/page.tsx`,
  `operations/dashboard/page.tsx`.
- **Zero permanent mobile/tablet e2e coverage existed** — `playwright.config.ts`
  extended with 2 new projects (`mobile-chrome`/`Pixel 5`,
  `tablet-chrome`/`iPad Pro 11`, both still the single pre-installed Chromium
  binary, no separate browser needed), scoped via `testMatch` to a new
  `e2e/browser-device-compat.spec.ts` that asserts zero horizontal overflow and
  reachable form fields across the same 4 routes Lens 3 verified manually —
  converting throwaway investigation evidence into a permanent regression
  guard. **Caught a real config bug before Tier C**: `devices["iPad Pro 11"]`'s
  own `defaultBrowserType` is `webkit` (a real iPad runs Safari); spreading it
  without an explicit `defaultBrowserType: "chromium"` override made the first
  draft try to launch the absent WebKit binary — a real Tier A gate failure,
  fixed before commit.

**4 findings registered, not fixed, each with a named owner:**

- **`ISS-2026-244`** (Low, `TRACKED_GAP`) — Safari (WebKit) and Firefox are
  structurally untestable in this sandbox (no binary at `/opt/pw-browsers`,
  environment explicitly configured not to fetch more) — the same class of
  firm constraint `HDN-380` found for the Supabase auth backend.
- **`ISS-2026-245`** (Low) — no PWA manifest/service worker exists anywhere;
  RPD-004's "online-first responsive PWA" language should be scoped to
  "responsive web app," not an installable PWA, or a real manifest built —
  outside this checkpoint's "no new product features" boundary either way.
- **`ISS-2026-246`** (Low) — 6 shared UI primitives (`IconButton`, `Checkbox`,
  `ToastProvider`, `Dialog`, `Drawer`, `CommandMenu`) confirmed unused in any
  real feature screen (only the internal design-system showcase references
  them) — this checkpoint fixed the ones with a real defect anyway, since
  they're the correct target for future adoption. **A prior investigation
  claim that `DataTable` was also unused did NOT reproduce** — independently
  re-verified with a precise import-path grep and found 56 real feature pages
  import it; corrected before propagating a false claim.
- **`ISS-2026-247`** (Low) — 19 of 95 tables still have no overflow wrapper
  after this checkpoint's own fix of the 4 worst offenders (down from 23);
  enumerated by path (see §6), a mechanical sweep for a future task.

   no hang). One pre-existing, out-of-scope 500 was found and correctly
   diagnosed as the backend-unreachable condition every other spec already
   discloses, reproduced identically on desktop to rule out a device-specific

## 11. Taxonomy

No new class needed — every fix this checkpoint made (touch-target sizing,
viewport-relative width capping, table overflow wrapping, device-preset e2e
scoping) is an application of this repository's own already-established
conventions (the `overflow-x-auto`+`min-w` pattern already used by 73 other
tables; `h-9 w-9`-style fixed sizing already the codebase's own primitive
convention, just too small) rather than a novel recurring defect shape. The
`devices["iPad Pro 11"]` defaulting to WebKit is a genuine Playwright-tooling
gotcha worth a one-line note for any future project using a tablet device
preset in this sandbox, but is narrow enough (one specific preset, one
specific sandbox constraint) that it doesn't warrant its own taxonomy class —
noted in `playwright.config.ts`'s own inline comment instead, where a future
editor of this exact file will actually see it.
