**`ISS-2026-145` (matrix item 1) is `RESOLVED`.**
`scripts/db-tests/rbac-enforcement.sql`'s ATW-032/`ISS-2026-032` actor-identity
call-graph sweep built an `fn`/`edge` recursive CTE whose `edge` construction was a
full `fn × fn` self-join (~2,700² pairs at current schema scale) with one regex
match per PAIR against each candidate function's own `pg_get_functiondef()` output —
15-20+ minutes of pure CPU standalone, paid by every future checkpoint's own Tier A
gate as the schema keeps growing. Rewritten to a one-pass `regexp_matches()`
extraction (one regex evaluation per FUNCTION, not per pair) — the identical
technique already used, unmodified, in this same file's own sibling
ATW-032/`ISS-2026-033` block two sections above. Only `edge` construction changed;
the `covered` recursive CTE's own multi-hop transitive-closure walk (a function
covered because it calls a helper that calls another helper that finally reaches
`evaluate_permission`/`assert_actor_is_session_identity`) is byte-identical to
before, so the invariant proved is unchanged, not weakened.

**Live-verified with a same-schema matched-pair run, not a before/after comparison
across two separate database builds** — deliberately closing the accept-on-faith
gap a naive rebuild-then-retime comparison would carry: both the original and the
rewritten query ran in the same transaction, against the same disposable database
(2,700 functions, 328 migrations applied), with no rebuild in between. Original:
**692,092.8ms** (~11.5 minutes). Rewrite: **556.4ms**. Verdicts: **byte-identical**
(both empty — no unguarded function on the fully-migrated schema). **Speedup:
1244×.** Full `bash scripts/db-tests/run.sh` (229 files) re-run clean afterward,
`ALL PASSED`, confirming no other file's own assumptions about this block broke.
