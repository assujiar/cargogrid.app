## 1. What this checkpoint builds

HRT-278 is the fifth Phase 7 (HRIS/Ticketing) capability, built directly on `HRT-274` (Employee Master, `VERIFIED`), `HRT-275` (Organization and Position Linkage, `VERIFIED`), `HRT-276` (Recruitment/ATS, `VERIFIED`), and `HRT-277` (Onboarding/Offboarding, `COMPLETED`, own Tier C pending as part of this same batch). ## 3. Source/config decisions (disclosed, not left implicit)

All eleven numbered decisions are recorded directly in the migration's own header comment (`supabase/migrations/20260730900000_create_hris_attendance.sql:1-118`) — summarized here:

1. **Break/rest-period events are out of scope.** `event_type` is closed to `('clock_in', 'clock_out')` — the prompt's own main flow (§21) never names a break event. Deferred to a future checkpoint (most plausibly Prompt 281, Overtime and Timesheet).
2. **Shift/Roster (Prompt 279) does not exist yet.** "Effective shift" is satisfied by the policy's own `workday_start_time`/`workday_end_time` window, not a per-employee roster — `attendance_sessions` carries no `shift_id` placeholder column at all (a FK to a table that doesn't exist yet cannot be added correctly in advance). Prompt 279 is expected to add it additively, mirroring HRT-275's own `position_id` precedent.
3. **Policy is a bespoke versioned table, not PLT-121's Configuration Engine** — a small, strongly-typed, geography-bearing structure benefits from real CHECK constraints, mirroring HRT-277's own checklist-template reasoning.
4. **Location/device data is minimized structurally.** `location` is populated ONLY when the resolved policy's `location_enforcement_mode` requires evaluating it; geofence evaluation itself applies ONLY to the two live self-service channels (`mobile_web`/`kiosk`) — `manual_hr` and `device_import` are both structurally exempt (self-found during this checkpoint's own adversarial testing, §7 item 1).
5. **Corrections are a direct propose/decide workflow (HRS:Edit propose, HRS:Approve decide)** — NOT routed through PLT-123's Approval Engine, since that would hard-fail every correction for any tenant that hasn't separately configured approval routing for an unrelated domain. Mirrors `app.employee_position_assignments` (HRT-275) exactly.
6. **Device import reuses the real PLT-131/132 staged-import pipeline exactly** (the sixth-plus adopter) — the domain-specific validate/commit pair calls the SAME internal ingestion engine (`app._ingest_attendance_event`) the live clock path calls, never a second independently-hardened write path.
7. **Exception recalculation is a bounded (≤92-day), synchronous RPC, not a literal background-worker job** — this repository has no live job worker anywhere yet (standing `ISS-2026-015`); enqueuing a job nothing will dequeue would not actually be async. If real volume later proves this insufficient, `app.enqueue_job`/`app.claim_next_job` is the already-proven primitive to route through then.
8. **Sensitive free-text/location fields are column-restricted from this, the first, migration** — never retrofitted (the exact defect class HRT-276's own Tier C review found and had to fix after the fact).
9. **Cancel/reject never leaves a dependent process silently implying resolution is in flight** — rejecting or cancelling a correction request reopens its linked exception back to `open`.
10. **Anti-spoofing is structural.** `app.record_attendance_clock_event` carries no employee-id-shaped parameter at all — the acting employee is resolved exclusively from the caller's own validated session identity.
11. **RBAC bars match blast radius, not surface category** — `waive_attendance_exception` requires `HRS:Override` (the same bar as `app.terminate_employee`), never merely `HRS:Edit`, designed against HRT-277's own worst finding (authority-bar mismatch) from the start.

## 4. Security/access model

- **RLS:** every one of the 6 new tables carries the hardened default-deny SELECT policy (`(has_active_tenant_membership and not actor_holds_customer_user_layer) or is_supreme_admin()`), proven live against `anon` (schema-privilege denial) and a forged cross-tenant staff session (zero-row RLS-level denial, not merely RPC-level) in `scripts/db-tests/hris-attendance.sql`.
- **RBAC:** every write RPC gates through `app.evaluate_permission(actor, tenant, 'HRS', action)`. Blast-radius-matched bars: `Create`/`Edit` for routine authoring, `Approve` for policy-publish/correction-decide/payroll-approve, `Override` for exception-waive, `Import` for device-import commit.
- **The "fold non-member into not-found" primitive is applied uniformly** — every primary-row lookup follows `if not found or not has_active_tenant_membership(...) then raise ..._not_found`, so a cross-tenant caller receives a uniform not-found, never a real tenant_id/row-existence disclosure. Applied from the start (verified live: a forged `att2` session probing an `att1` session id gets `session_not_found`, not a permission-denied that would confirm the row's existence).
- **Column-restricted grants** (§3 decision 8) — `authenticated` has no column-level SELECT on `location`/`raw_payload`/`reason`/`decided_reason`/`waive_reason`/`resolution_note`; `service_role` has full access. Verified live via `has_column_privilege` in the db-test suite, both directions (excluded columns genuinely denied, retained columns genuinely still readable — never over-restricted).
- **Self-approval is blocked on every governed decision, not just the primary one** (taxonomy C-18) — `decide_attendance_correction` blocks an actor deciding their own request even when they happen to also hold `HRS:Approve` (self-found and live-tested); `waive_attendance_exception` blocks the identical self-waive case (self-found during this checkpoint's own Tier B taxonomy walk, §6/§7 item 2, before the reviewer stage — a genuine gap the first draft had).
- **Concurrency:** every write RPC with a version parameter repeats `record_version = p_expected_version` in the terminal `UPDATE`'s own `WHERE` clause; `decide_attendance_correction`/`cancel_attendance_correction`/`acknowledge_attendance_exception`/`waive_attendance_exception` all lock their target row `FOR UPDATE` before deciding. The clock-in race (no pre-existing row to lock) is closed by the `(tenant_id, employee_id, work_date)` unique constraint as the real structural safety net — live-reproduced with two genuinely concurrent OS processes (§7 item 4).

## 7. Self-found defects (found and fixed during this checkpoint's own adversarial testing, before commit)

Found via iterative, honest `psql`-driven testing against a live disposable Postgres 16 database, including two real concurrent OS processes, not shipped and found later:

1. **Geofence enforcement blocked every manual HR entry and every device-import row against a required-geofence policy.** The first draft applied `location_enforcement_mode <> 'none'` uniformly to all four source channels; live-tested by publishing a real `required`-geofence branch policy, then attempting a manual HR entry and a device-import commit against an employee under that policy — both failed with `location_required`, since neither HR nor a device-import row ever supplies a coordinate. **Fixed** by exempting `manual_hr` and `device_import` from geofence evaluation entirely (decision 4's own final form), disclosed with full reasoning in the migration header rather than silently narrowed.
2. **`waive_attendance_exception` had no self-approval block.** Found during this checkpoint's own mandatory Tier B taxonomy walk (C-18), not by a db-test failure — an actor holding `HRS:Override` could waive an exception on their own attendance. **Fixed** by adding the identical `get_self_employee`-based check `app.decide_attendance_correction` already had, with a new regression assertion.
3. **`commit_attendance_device_import_job` skipped the intermediate tenant-membership fold every established staged-import precedent uses.** Found during the C-05 taxonomy walk — the function went straight from "job exists" to `evaluate_permission`, omitting the `app.check_import_export_job_authority` call `commit_employee_import_job`/`commit_vendor_rate_import_job` both have. **Fixed** by adding the identical check for parity, matching the established pattern exactly rather than deviating.
4. **Real, live two-process concurrency race on double clock-in** — designed against from the start (decision 10/C-04) and then actually reproduced, not merely reasoned about: two genuinely concurrent `psql` OS processes both attempted `clock_in` for the same never-clocked-in-today employee. Result: exactly one session was created; the losing process received a real Postgres `unique_violation` on the `(tenant_id, employee_id, work_date)` constraint, zero duplicate sessions. Recorded as the concrete evidence for this class in §6/§4, not merely asserted.
5. **`search_path` omitted `public` in six functions that write to a geography-CHECK-constrained table.** `app.validate_geography_point`/PostGIS's own `geometry` type live in the `public` schema (not `app`); several functions (`_ingest_attendance_event`, `create_attendance_policy_version`, `record_attendance_clock_event`, `publish_attendance_policy_version`, `commit_attendance_device_import_job`) originally declared `set search_path = app, pg_temp` only, which broke ANY write to `attendance_events`/`attendance_policy_versions` (even one that never touched the geography column itself, since Postgres re-evaluates every row-level CHECK constraint on every UPDATE regardless of which columns changed) with `type "geometry" does not exist`. **Fixed** by adding `public` to each affected function's own `search_path`, matching the exact pattern every prior geofence-touching function in this repository (e.g. `20260730090000`) already uses.
6. **`app.commit_attendance_device_import_job`'s per-row `device_label` was silently dropped.** The shared `_ingest_attendance_event` engine has no `device_label` parameter (only the self-service clock RPC sets it via a follow-up `UPDATE`); the device-import commit path never applied the same follow-up, so every imported row's `device_label` stayed null even when the source CSV supplied one. **Fixed** by adding the identical follow-up `UPDATE` to the commit function.
7. **Two test-fixture-only bugs**: a `select *` against a column-restricted table in the db-test file itself (fixed by selecting explicit columns, see C-17 above); several `request.jwt.claims` staleness bugs in the db-test file, where a GUC value set by an earlier `set_config` call persisted across later superuser-context blocks within the SAME psql session and tripped `assert_actor_is_session_identity`'s mismatch guard on an unrelated actor — fixed by explicitly clearing `request.jwt.claims` to `'null'` after every `reset role;` in the test file, and by wrapping the one remaining unwrapped superuser-context policy-authoring block with its own real `set_config`/`set role authenticated` pair.

Consistent with this repository's own disclosed history (HRT-274 found 7, HRT-275 found 2, HRT-276 found 12, HRT-277 found 11), this checkpoint's own honest adversarial pass — including its own mandatory Tier B taxonomy walk, which caught 2 of the 7 items above (2, 3) that live db-testing alone had not yet surfaced, and a genuine live two-process concurrency reproduction (4) — found and fixed 7 real defects before commit (test-fixture-only bugs counted together as one item per this repository's own HRT-275/276 precedent for reporting a shared-root-cause class as one item).
