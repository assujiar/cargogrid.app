## 6. Finding and fix — `supabase/config.toml` declared seeding against a file that never existed

**Finding.** `supabase/config.toml`'s `[db.seed]` block read:

```toml
[db.seed]
enabled = true
sql_paths = ["./seed.sql"]
```

`supabase/seed.sql` **does not exist and has never existed** in this repository (`git log
--follow -- supabase/seed.sql` returns nothing) — a `supabase init` boilerplate default that was
never cleaned up, sitting unnoticed because this project's own db-test harness
(`scripts/db-tests/run.sh`) never reads `config.toml` at all and so never exercises this path.
The Supabase CLI itself (`supabase db reset`, the tool's own standard clean-rebuild command,
distinct from but parallel in purpose to this repository's bespoke harness) **was not available in
this execution environment** (`supabase: command not found`) to empirically confirm its exact
failure mode against a missing seed file — disclosed rather than guessed at. What is certain,
directly from the CLI's own config schema and this repository's own git history, is that the
declared configuration and repository reality have never matched: a real developer or CI step
invoking `supabase db reset` locally would depend on a file that was never committed.

**Fix**, minimal and matching actual practice rather than inventing seed data that corresponds to
nothing: `enabled` set to `false`, with a comment recording why, referencing this checkpoint.
`sql_paths` is left in place (harmless while `enabled = false`, and preserves the original intent
if a real seed script is ever added later) rather than deleted, so the change is a single-line
behavioral flip with its reasoning attached, not a structural rewrite.

This is a **tooling-configuration correctness fix directly inside this checkpoint's own charter**
(Prompt 396 §13, "verify... seed/reference data... as applicable," §20 step 5, "apply only
authorized release-safe correction if required") — not a new feature, not a schema change, and it
touches no migration, no application code, and no live database.
