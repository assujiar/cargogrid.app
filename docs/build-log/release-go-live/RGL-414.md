## 3. Why the authorized SHA is the commit it is, and not the commit containing this decision

Worth stating, because it looks like an off-by-one until you follow it through.

`scripts/release/check-go-decision.ts` compares `authorizedCommitSha` against
`VERCEL_GIT_COMMIT_SHA` — the commit being built — and refuses on any mismatch, deliberately
using a full-length comparison so no prefix collision can authorize the wrong commit. A file
naming the SHA of the commit that contains it is impossible to write: a commit's hash covers its
own contents, so adding the decision changes the hash the decision would have to name.

That is not a defect in the gate, because Git-triggered production builds are disabled at the
same time: `vercel.json` sets `git.deploymentEnabled.main = false`. The intended path — the one
the plan states — is a **manual promote** of a build that already exists and has already been
verified.

So the decision names `d48b589`: the exact commit whose build is promoted. The decision is
recorded *after* that artifact exists and *about* it, which is the correct order for a decision
that is supposed to rest on evidence. This record and `GO_DECISION.json` land in the commit
after, as the audit trail of a decision already made.

One consequence, and it is the safe direction: a future Git-triggered production build at the
*later* commit would find `authorizedCommitSha` naming `d48b589`, not itself, and refuse. A new
deployment needs a new decision. That is the gate working, not a problem to route around.

## 4. What "publish" turned out to mean, and the decision taken

`RGL-413.md` §6 established live that `cargogrid.app` is served by **Cloudflare**, renders a
different site built with a website builder, returns `404` on `/api/health`, and has never been
attached to this Vercel project. Promoting a production build therefore does **not** put
CargoGrid on that domain.

Put to the owner with the consequence stated — that a cutover would *replace* the page currently
live there — the decision was **"Pakai subdomain saja"**: leave `cargogrid.app` as it is, and
give CargoGrid a subdomain instead. Nothing currently public is replaced.

The DNS and domain-attachment steps are outside this session's access and are written up for the
owner to run in `docs/runbooks/human-execution-pack.md`. Tracked as `ISS-2026-311`.
