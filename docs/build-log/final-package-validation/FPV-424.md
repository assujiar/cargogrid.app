## 4. Existing-code safety does not depend on prompts remembering to ask for it

Three mechanical controls run regardless of what any prompt says:

- **`scripts/git/check-protected-paths.ts`** — `docs/blueprint/**`, the prompt package, applied
  migrations and real secret files are `FORBIDDEN`; `docs/architecture/**` and `docs/runtime/**`
  are `CAUTION`. Runs per-prompt via `git:check-paths` and again in CI on the PR diff.
- **`AGENTS.md` "Scope and refactoring"** — one feature slice, one module boundary, 1–3
  migrations, ~5–15 changed files; "Fix only task-caused failures"; broad refactors need a
  dedicated prompt and ADR.
- **`AGENTS.md` migration rule** — "Never edit an applied migration; add a new migration",
  enforced git-status-aware so a *new* migration is not falsely flagged.

**The one narrowing of these controls is this step's own**, and it is recorded rather than
silent: `CON-016`/`ADR-0026` downgrade five package metadata files to `CAUTION` for Step 17 only,
matched literally; all 324 prompt files and all 18 step READMEs stay `FORBIDDEN`. A lane auditing
scope safety has an obvious conflict of interest in the one scope grant its own step created, so
it is named here explicitly.
