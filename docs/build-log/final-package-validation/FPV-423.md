## 1. Scope

Prompt 423 §4: audit whether a new agent can understand and use the package without prior
conversation context. This is the question the whole package exists to answer, and the one
easiest to answer wrongly — everything looks complete to someone who already has the context.

## 2. Method: read it as a stranger would

The audit was run as an entry simulation, following only what the package itself tells a reader
to do next, starting from `START_HERE.md` and never using knowledge from this session's other
lanes. At each step the question was: *does this file tell me what to read next, or do I have to
already know?*

## 6. Finding `FPV-F006` — the entry point tells a new agent the package is already validated

**Severity: MEDIUM.** `START_HERE.md` §8 reads:

> "At this checkpoint, Step 0 through Step 17 package files are generated **and validated** as
> prompt-package artifacts."

The same claim appears in `00-control/06_PACKAGE_BUILD_STATUS.md`, whose header declares
**`Current checkpoint: FINAL_PACKAGE_VALIDATED`**, dated **2026-07-13** — the date the package
was *generated*.

**Why this is a real defect and not a quibble.** `FINAL_PACKAGE_VALIDATED` is the closure state
that Prompt 430 alone is authorized to set, and Prompt 430's runtime execution is happening now,
in this Step 17. The package therefore asserts its own validated state as a generation-time
property, before the validation that establishes it has run. A new agent reading `START_HERE.md`
§8 and `06_PACKAGE_BUILD_STATUS.md` in sequence — steps 4 and 8 of its own onboarding — is told
the package is validated by an artifact that predates the validation by six weeks.

This lane found it precisely by refusing to use session context: a reader who knows Step 17 is
running now discounts the claim automatically. A stranger cannot.

**Disposition: registered, not fixed by this lane.** The correction is a wording change to two
of the five files `CON-016` makes correctable, and it is a genuine mechanical inconsistency — but
`FPV-430` is the only lane authorized to determine what the package's real closure state is.
Correcting it before that verdict exists would be inventing the answer. **Routed to `FPV-429`
(START_HERE) and `FPV-430` (closure) to apply once the verdict is known.**

## 9. Tier C — adversarial round

**Lens 1, spec compliance.** Prompt 423 §33 met.

**Lens 2, the context-contamination attack — the one that matters here.** An agent that has just
audited the package for eight lanes is the *worst* possible judge of whether a stranger could use
it. The mitigation was to follow only `START_HERE.md`'s own instructions and to treat every claim
it makes as something a stranger would believe. That is exactly what surfaced `FPV-F006`: the
statement "generated and validated" is invisible to someone who knows the validation is running
right now, and load-bearing to someone who does not.

**Lens 3, is the range check real?** It compares the declared range to the sorted set of actual
file numbers per directory, so it detects a gap, an extra, and an off-by-one at either end — not
merely a matching count. A count-only check would pass a directory missing prompt 200 and
carrying a spurious prompt 249.

**Lens 4, scope discipline.** No package file touched. `FPV-F006` is inside `CON-016`'s
correctable set and was still **not** applied, because the correct wording depends on a verdict
`FPV-430` has not yet reached. Fixing it now would fabricate the closure state.

**Round result:** one real package defect found and registered. `VERIFIED`.
