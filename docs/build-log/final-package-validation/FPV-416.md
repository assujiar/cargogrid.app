## 4. Finding `FPV-F003` — 14 prompts render as code blocks, and hid from the validator

**Severity: MEDIUM.** Fourteen capability prompts have **every line of their body indented by
four spaces**. In Markdown that makes the entire document — the metadata block, all 36 headings,
every table — a single preformatted code block.

The affected files, all of them:

`10-phase-05-advanced-tms-wms/`: `222_DISPATCH_BOARD`, `223_FLEET_DRIVER`,
`224_ROUTE_LOAD_PLANNING`, `225_FIRST_MIDDLE_LAST_MILE`, `226_GPS_TELEMATICS_INTEGRATION`,
`227_CAPACITY_UTILIZATION`, `228_ADVANCED_MILESTONE_EXCEPTION`, `243_HIGH_VOLUME_OPERATIONS`,
`245_…INTEGRATED_VERIFICATION`, `246_…INTEGRITY_SECURITY_HARDENING`,
`247_…DOCUMENTATION_HANDOFF` (11) · `13-phase-08-customer-portal-loyalty/`: `305_TRACKING`,
`306_SHIPMENT_MONITORING` (2) · `14-phase-09-intelligence-enterprise/`:
`343_MAPS_GPS_TELEMATICS_INTEGRATIONS` (1).

**The content is intact.** Each of the 14 carries all 36 fields with real content; nothing is
missing. The defect is presentation and machine-parseability, not substance — which is exactly
why it survived this long.

**Why it matters, concretely.** It defeated this session's own validator. The first version of
`check-prompt-package.ts` anchored its heading and metadata patterns at line start, so it
skipped all 14 files silently and reported "324 structured prompts, zero duplicate IDs" — a
figure that was true of 324 files while reading as though it covered every prompt in the
package. **The 14 files' `Prompt ID` and `Package document` values had never been checked for
uniqueness by anything.** They now are: with indentation-tolerant parsing the real figure is
**338** structured prompts, and uniqueness still holds across all 338.

Any future agent or tool that parses these prompts by heading hits the same wall, and a human
reader sees an unreadable wall of preformatted text instead of a structured prompt.

**Disposition: registered, not fixed.** De-indenting 14 prompt files is not a mechanical
metadata correction, and prompt files remain `FORBIDDEN` under `ADR-0026` decision 2. Proposed
patch in the gap/risk register.

**Gate treatment.** `package:check` reports `INDENTED_BODY` as an **ERROR** by default. The 14
known files are pinned in an exhaustive `KNOWN_TEMPLATE_VARIANT_FILES` allowlist and downgraded
to **WARN**, so the gate stays usable while the defect stays visible — the discipline
`BUILD_EXECUTION_PROTOCOL.md` §5.5 requires for a pre-existing failure. **A fifteenth file with
this defect is an ERROR and fails CI**, and a test asserts the allowlist matches the real
package exactly, so it cannot drift silently in either direction.

allowlist, and it is narrow: an allowlisted file may use the legacy wording **only for its own
field number**; any other heading deviation is still an ERROR even in an allowlisted file.

## 9. Tier C — adversarial round

**Lens 1, spec compliance.** Prompt 416 §33: checklist complete (§2), findings evidence-backed
with paths (§4, §5), blockers registered (both), package/runtime distinction preserved, next
prompt clear. Met.

**Lens 2, re-derivation of the findings.** `FPV-F003` was confirmed by reading
`222_DISPATCH_BOARD_PROMPT.md` directly and observing the four-space indent on the metadata
block and on `## 1. Prompt ID` — not inferred from the validator's silence. The count was then
re-derived independently with `grep -rlP '^\s+## 1\. Prompt ID'`, which returns exactly the same
14 files.

**Lens 3, adversarial review of this lane's own tooling changes.** Three defects were found in
the validator during this lane and fixed before anything was trusted:

1. **Self-loops that were not there.** After indentation-tolerant parsing, four Phase 5 prompts
   reported `NEXT_SELF_LOOP`. All four were false. Their §36 reads "release ATW-247 **after
   ATW-246 is verified**" — the self-reference is a *precondition*, not a successor. Fixed by
   excluding `after … verified` clauses.
2. **The first fix was too literal.** `226_GPS_TELEMATICS_INTEGRATION` survived it, because its
   wording is "after all required ATW-226 **child tasks** are verified". Generalized to match
   the clause rather than the exact phrase, bounded to one sentence.
3. **`Prompt 248 alone may close Phase 5`** was being read as a successor edge. It is a
   prohibition, like the already-handled `only Prompt N may`. Excluded.

Each is pinned by its own test using the real Phase 5 wording, so a future refactor cannot
silently reintroduce it. Explicit edges settled at **174**.

**Lens 4, scope discipline.** No package file touched; both findings registered rather than
applied. The `CON-016` authority was available and correctly unused — de-indenting prompt files
is not a mechanical metadata correction.

**Round result:** three real defects found in this lane's own tooling, all fixed and tested; two
real defects found in the package, both registered. `VERIFIED`.
