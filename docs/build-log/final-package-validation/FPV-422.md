## 3. The state a resuming agent reads

Resume is only possible if state outlives the session. `01-agent-governance/` supplies five
durable ledger templates, and each has a live repository-native instance under `docs/runtime/`:

| Template | Instance | What it preserves |
|---|---|---|
| `13_BUILD_STATUS_TEMPLATE.md` | `CARGOGRID_BUILD_STATUS.md` | Checkpoint, gates, phase, environment, readiness |
| `14_TASK_LEDGER_TEMPLATE.md` | `TASK_LEDGER.md` | Per-task state, dependency, evidence, resume point |
| `15_CHANGE_MANIFEST_TEMPLATE.md` | `CHANGE_MANIFEST.md` | Change, compatibility, rollout, rollback |
| `17_ERROR_LEDGER_TEMPLATE.md` | `ERROR_LEDGER.md` | Failure, impact, root cause, recovery, verification |
| `18_KNOWN_ISSUES_TEMPLATE.md` | `KNOWN_ISSUES.md` | Issue, workaround, release effect, closure |
| `19_HANDOFF_TEMPLATE.md` | `HANDOFF.md` | Context-independent checkpoint and resume handoff |

`AGENTS.md` "Required pre-flight" makes reading all seven `docs/runtime/` files mandatory before
any edit, so the resume state is not merely available — it is on the critical path.

## 4. The resume rule is bounded in the right direction

`START_HERE.md` §7: "If a task fails or is interrupted, resume from the latest verified
checkpoint using the task ledger, error ledger, change manifest, known issues and handoff. **Do
not restart the full build unless the repository or database is no longer trustworthy and
rollback authority is recorded.**"

Two properties worth naming: resume is the default and full restart is the exception; and full
restart is gated on *recorded rollback authority*, not on an agent's judgement. That is the
correct direction for a 430-prompt build — the failure mode being prevented is an agent
discarding verified work because resuming looked harder.

## 5. Restartability is demonstrated, not only specified

This repository has actually exercised it. `ERR-2026-001..004` in `ERROR_LEDGER.md` record real
failures — including a Sev-1 repository-wide function-privilege gap and a parallel-session merge
corruption — each `RECOVERED` from a checkpoint rather than by rebuilding. Step 16's own
`RGL-412` closed a 22-lane range that had been resumed across multiple sessions. Evidence that
the resume machinery works is stronger than evidence that it exists.

**Lens 1, spec compliance.** Prompt 422 §33 met.

**Lens 2, would this audit catch a package that cannot resume?** The weak version checks that a
resume template exists and stops. A package can have a resume template and still be
unresumable if state does not survive the session. That is why §3 traces each template to a live
`docs/runtime/` instance and to `AGENTS.md`'s mandatory pre-flight read — the mechanism that
makes the state actually consulted rather than merely stored.

**Lens 3, the direction of the resume rule.** Checked deliberately: a rule saying "restart when
in doubt" would satisfy the letter of Prompt 422 while defeating its purpose. `START_HERE.md` §7
does the opposite and gates full restart on recorded rollback authority.
