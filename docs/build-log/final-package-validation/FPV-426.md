## 3. Finding `FPV-F007` — 17 prompt files carry a version the manifest does not know about

**Severity: MEDIUM.** Seventeen files declare a `-multisource-gps`-suffixed version that is also
**one minor version ahead** of their manifest row:

| Files | Declared in file | Manifest row says |
|---:|---|---|
| 14 (all of `10-phase-05-advanced-tms-wms`'s prompts, incl. `219` README, `220` kickoff, `248` closure) | `0.12.0-multisource-gps` | `0.11.0` |
| 2 (`13-phase-08-customer-portal-loyalty`) | `0.15.0-multisource-gps` | `0.14.0` |
| 1 (`14-phase-09-intelligence-enterprise`) | `0.16.0-multisource-gps` | `0.15.0` |

A revision was applied to these files and the manifest was never updated — exactly what the
manifest's own §1 rule 2 forbids: "finalized files are revised only through change summary and
version increment". There is no `-multisource-gps` row anywhere in the manifest's version
history, so the revision is unrecorded.

**Corroboration, not coincidence.** Eleven of the fourteen Phase 5 files are the same files
`FPV-F003`/`FPV-F004` found with indented bodies and legacy heading wording. Three independent
defects — indentation, heading vocabulary, version suffix — land on one overlapping cluster.
That is a single unrecorded revision pass, not three unrelated slips.

**Disposition: registered, not fixed.** The mismatch is between prompt files (`FORBIDDEN`) and the
manifest (correctable), and **which side is authoritative is a judgement, not a mechanical
fact**: `06_PACKAGE_BUILD_STATUS.md` independently says `0.11.0` for these files, so two control
documents agree against seventeen prompt files. Writing `-multisource-gps` into the manifest would
propagate a version scheme that contradicts the build status. `ADR-0026` decision 5 is explicit —
when in doubt, it is a finding.

## 4. Finding `FPV-F008` — four control files and the manifest disagree on the version *scheme*

**Severity: LOW.** `00_PACKAGE_README.md`, `06_PACKAGE_BUILD_STATUS.md`,
`07_PROMPT_PACKAGE_MANIFEST.md` and `START_HERE.md` each declare `0.18.0-step17`; their manifest
rows (`M-000`, `M-006`, `M-007`, `M-431`) say `0.18.0`.

This resolves `FPV-414`'s deferred question. It is **not** a numeric disagreement — it is two
version notions coexisting: the qualified package version in the file header versus the bare step
version in the manifest's Version column. `05_REQUIREMENT_COVERAGE_MATRIX.md` declares `0.18.0`
in both places and is consistent, which shows the package does not apply one convention uniformly.

**Disposition: registered, not fixed.** Both readings are defensible, so under `ADR-0026`
decision 5 this is a finding. Prompt 430 item 1 is unaffected: it requires the control *files* to
reference `0.18.0-step17`, and all four do.
