## 2. Design decisions (cited, not re-derived)

Full rationale lives in the migration's own header (`supabase/migrations/20260806400000_create_intelligence_forecasting_recommendation.sql`, 11 numbered decisions). Summary:

1. **Forecasts can never create commitments, budgets, vendor awards, maintenance orders or customer actions autonomously.** No function writes to any existing Finance/Commercial/Procurement/Operations table. `app.record_forecast_planning_decision` records a manager's own planning-decision NOTE only — never a write into any real commitment/budget/vendor-award/maintenance-order table.
2. **A small-inference-cohort control is a real, structural mask** — whenever the governed request's own output reports `cohortSize < 10` (a disclosed, fixed threshold), `app.get_forecast_job` masks any customer/name/email/phone/account/address-shaped key at any nesting depth, reusing `AI:Approve` as the "may see small-cohort detail anyway" elevation tier — mirroring IAE-023's own recursive masking shape.
3. **Insufficient data is a real, distinct terminal status** (`insufficient_data`), never a fabricated forecast — `app.record_forecast_job_outcome` reads the governed request's own `insufficientData` flag and lands the job there with a defensively-extracted `data_quality_note`, never `succeeded` with a fabricated `predicted_value`.
4. **`predicted_value`/`cohort_size`/`data_quality_note`/`insufficientData` extraction is defensive**, mirroring IAE-022/024's own parse-helpers exactly — malformed input yields null/false, never a crash.
5. **Feedback and evaluation are two genuinely distinct tables/writers** — `app.forecast_job_feedback` (a manager's usefulness judgment + planning note) and `app.forecast_job_evaluations` (real observed-outcome accuracy/drift evidence).
6. AI dispatch reuses `dispatchAiGovernedRequest` (IAE-019) unmodified — `feature_code = 'forecasting_recommendation'`, `correlation_record_type = 'forecast_job'` (self-correlated, mirroring IAE-023's optimization scenario, since a forecast's own scope can span many customers/vendors/SKUs with no single stable external entity).
7. No new entitlement module.
8-10. Proactively applied lessons from IAE-020..024: `SECURITY DEFINER` + `assert_actor_is_session_identity`; explicit table aliases in `RETURNS TABLE`; `IS DISTINCT FROM` for nullable correlation cross-checks; every `RAISE` `%` placeholder carries a real argument (IAE-024's own self-caught compilation-time bug, applied proactively here — none found this checkpoint).
11. Per `ERR-2026-004`: explicit `revoke execute on all functions in schema app from public`.
