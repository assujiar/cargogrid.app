## 8. Errors and self-caught fixes during this checkpoint's own work

- **Two Postgres "function identity" gotchas, both self-caught before commit**: adding a `p_depth integer default 0` parameter to the three masking/redact functions via a plain `CREATE OR REPLACE FUNCTION` silently created a second, overloaded function instead of replacing the original (Postgres does not treat a widened parameter list, even with a default, as the same function identity for replacement purposes) — caught immediately on the first migration-apply attempt (`function name ... is not unique`), fixed by an explicit `DROP FUNCTION` first for each of the three, mirroring `IAE-029`'s own already-documented precedent for `capture_audit_event`.
- **A real Postgres NaN-semantics bug in this checkpoint's own first draft, self-caught by live testing, not code review alone**: Fix 3's original cost check used `p_provider_unit_cost_amount <> p_provider_unit_cost_amount` as a NaN-detection idiom, correct for IEEE-754 floating point but WRONG for Postgres `numeric` — Postgres numeric explicitly treats `NaN = NaN` as `true` (to allow sorting/indexing), so the check never fired. Caught by running the new regression test itself and seeing it fail with "the call unexpectedly succeeded"; root-caused via a direct `psql` probe (`select 'NaN'::numeric <> 'NaN'::numeric` → `false`; `select 'NaN'::numeric >= 'Infinity'::numeric` → `true`) before writing the real fix, reusing the exact `x >= 'Infinity'::numeric` idiom Group 8's own IAE-035 RPO/RTO sanity check already established.
- **A test-fixture-ordering bug in this checkpoint's own first draft of the audit-linkage regression, self-caught by live testing**: the new regression block was originally inserted immediately after the pre-existing 12-arg `capture_audit_event` test, creating a SECOND `support_access_grants` row before a later, pre-existing test block's own `select ... order by requested_at desc limit 1` (an implicit "the one grant in existence so far" assumption) — breaking that later block's own event count. Fixed by moving the new regression to the very end of the file, after every block that relies on that ordering assumption.
- **A self-review-forbidden-vs-validation-check ordering issue in the `fraud-risk-assistance.sql` fixture, discovered when the pre-existing test file failed after Fix 1 landed**: several pre-existing negative-path assertions (empty reason, empty customer-safe-reason, identical reasons, already-held) all used the SAME actor who had also confirmed the review — now correctly blocked by the new self-review guard before ever reaching the validation each assertion was designed to test. Fixed by introducing a genuinely distinct second `AI:Approve`-holding actor (`v_approver1`) for the successful-hold path and every validation-only negative path, while adding a new, dedicated regression proving the self-review guard itself using the original confirming actor.
