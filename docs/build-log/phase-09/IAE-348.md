## 1. What this checkpoint builds

The FIRST real consumer of IAE-019's own AI governance boundary. A sales user requests AI assistance on a quotation; the system dispatches a real, governed AI request citing real, versioned rate/margin sources from the opportunity's own costing chain; a human reviews the suggestion and either dismisses it or explicitly accepts it into a real `app.quotations` draft — at which point the existing, wholly unmodified Commercial quotation submit → approve → send → customer-decision flow (COM-151 through COM-154) is the only path to any customer-facing commitment. No new send/accept mechanism is built here; this checkpoint's own scope is bounded to exactly the AI-suggestion-tracking layer sitting BEFORE that pipeline.

## 2. Design decisions (cited, not re-derived)

Full rationale lives in the migration's own header (`supabase/migrations/20260805080000_create_intelligence_ai_assisted_quotation.sql`, 9 numbered decisions). Summary:

1. **AI output can NEVER reach `app.quotations`/`app.quotation_lines` directly — structurally, not by convention.** The ONLY write path is `app.accept_ai_quotation_suggestion_as_draft`, and even it never parses or trusts the AI's own `output_payload` — only the human-submitted, explicitly-typed `p_accepted_lines`, handed unchanged to the EXISTING, UNMODIFIED `app.create_quotation_draft`/`app.add_quotation_line` (COM-151/152).
2. **Human edits and the final decision are recorded SEPARATELY from the AI suggestion, by construction.** The AI's own suggestion is immutable evidence in IAE-019's own `app.ai_governed_requests.output_payload`; this checkpoint's own `app.ai_quotation_suggestions` tracks only the human's review decision; the actual accepted lines live only in `app.quotation_lines` — three genuinely distinct tables, three genuinely distinct writers.
3. **"Low-confidence/no-source output blocks auto-draft acceptance" is a hard, structural gate at the ONE convenience RPC this blocks, never elsewhere.** `accept_ai_quotation_suggestion_as_draft` refuses unless the governed request's own `confidence_label` is `high`/`medium` (never `low`, never null) AND every accepted line cites a real `margin_calculation_id`.
4. **No new approval step is required before draft status.** Entering `draft` commits nothing customer-facing and is fully reversible; the real critical-status gate is the existing, unmodified COM-153/154 approval/send flow, unchanged by this checkpoint.
5. **`create_quotation_draft`/`add_quotation_line` run inside ONE function-call transaction** — any line failing their own independent validation rolls the whole `accept_ai_quotation_suggestion_as_draft` call back atomically.
6. **The AI dispatch reuses `dispatchAiGovernedRequest` (IAE-019) completely unmodified** — `feature_code = 'ai_assisted_quotation'`, `correlation_record_type = 'opportunity'`. Zero new rows in `app.integration_adapters`, zero new `app.jobs` job types.
7. **Authority reuses the existing `COM` module directly** — no new entitlement module.
8. **Every `authenticated`-granted function is `SECURITY DEFINER` plus `app.assert_actor_is_session_identity` from the very first draft** — the merged Batch 4 Tier C review's own most-repeated lesson, applied proactively.
9. Per `ERR-2026-004`: explicit `revoke execute on all functions in schema app from public;`.

## 7. Tier B — recurring defect taxonomy self-check

- **C-12/C-13 (`SECURITY DEFINER` authority, actor-identity)** — applied proactively to every `authenticated`-granted function from the first draft (design decision 8), the merged Batch 4 Tier C review's own most-repeated lesson.
- **C-05 (permission check after disclosure)** — `accept_ai_quotation_suggestion_as_draft` checks `COM:Create` before any read of the underlying governed request or any mutation; live-verified the suggestion remains `pending` after a rejected unauthorized attempt (§10).
- **Self-caught, before commit (three real bugs, none reached the applied migration until fixed):**
  1. **Nullable-column `<>` gap.** `record_ai_quotation_suggestion`'s own correlation cross-check used a bare `<>` against `correlation_record_type`/`correlation_record_id`, both nullable columns — `NULL <> 'opportunity'` evaluates to `NULL`, which plpgsql's `IF` treats as false, silently skipping the raise for a governed request with no correlation set at all. Fixed with `IS DISTINCT FROM`; a dedicated db-test regression block proves a null-correlation request is now rejected.
  2. **`RETURNS TABLE` column-shadowing ambiguity.** `get_ai_quotation_suggestion` declares `RETURNS TABLE(id uuid, ...)`, which implicitly declares `id` (and every other out-column name) as a plpgsql variable in the function's own namespace — its bare `where id = p_suggestion_id` lookup was ambiguous against the table's own `id` column, a real runtime error (`column reference "id" is ambiguous`) caught live by the db-test run, not by static reading alone. Fixed with an explicit table alias (`s.id`), matching the pattern the rest of the function already used correctly in its own `return query`.
  3. **CHECK-constraint-violating two-step write.** The original draft set `status = 'accepted'` in an early atomic-guard UPDATE, then a SECOND UPDATE set `accepted_quotation_id` afterward — the FIRST statement alone violated the table's own `ai_quotation_suggestions_accepted_shape_check` (which requires both fields change together), caught live on the very first successful-acceptance test. Fixed by reordering: `create_quotation_draft`/`add_quotation_line` now run BEFORE the suggestion's own atomic transition, and the single final UPDATE sets `status` and `accepted_quotation_id` together, keeping the WHERE-clause-only concurrency guard (Tier C fix 12's own lesson) while satisfying the constraint. A live 6-way concurrent-process race (§10) confirms zero orphaned quotation drafts survive from any losing caller.
- **ISS-2026-034-class (rate-limit/retry discriminator)** — not applicable; this capability has no retry/backoff surface of its own (the underlying dispatch's own retry posture is IAE-019's, unmodified).

No taxonomy class was skipped.

3. **`dismiss_ai_quotation_suggestion`'s atomic pending-only transition**: `insufficient_authority` for a `COM:View`-only actor; a real dismiss succeeds; a second dismiss on the same suggestion raises `ai_quotation_suggestion_not_pending`.
