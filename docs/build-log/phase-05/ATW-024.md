## 2. Design decisions (disclosed, migration headers)

### Deliverable A — `app.shipment_tracking_health` real writer (closes `ISS-2026-009`)

1. **Vehicle resolution reuses the exact, already-established join pattern** (`app.resource_assignments`, role='vehicle', is_current, active) verbatim from `app.detect_shipment_leg_tracking_health_signals`/`app._compute_shipment_leg_eta` (`ATW-228`) — no new resolution mechanism invented.
2. **Disclosed discrepancy against `ISS-2026-009`'s own wording** (an adversarial-review finding, resolved by disclosure rather than scope expansion): the issue's own text names `app.shipment_leg_tracking_sessions` ("`ATW-225`'s leg tracking sessions, including precedence/timing rules") as part of the required design; this migration resolves the vehicle at the shipment-order level only, mirroring `ATW-228`'s own identical simplification. For a multi-leg shipment serviced by genuinely different vehicles over time, `shipment_tracking_health` reflects "the" shipment-level assignment, not the currently-active leg's own handoff precedence. Recorded as a residual, narrower issue — see §7.
3. **Freshness is never reimplemented** — calls `app.get_vehicle_source_health()` (`ATW-226F`) rather than a second classifier.
4. **A live-reproduced HIGH-severity, pre-existing TOCTOU race** in `app.arbitrate_and_project_vehicle_position` (present since `ATW-226F`, `20260729390000`, carried through `ATW-226G`'s widening, inherited byte-for-byte into this migration's own widening) — a plain read-decide-then-blind-`ON CONFLICT`-write with no ordering guard, letting an older telemetry event that loses a race to commit last silently overwrite a newer, already-committed position. Directly violates that same migration's own header claim ("current position must never move backward... merely because it arrived later"). Live-reproduced via a controlled two-session race with a deterministic delay window; **fixed** with a per-vehicle `pg_advisory_xact_lock` taken as the first statement, fully serializing concurrent arbitration for the same vehicle, verified against 59,534 real concurrent conflicting-source transactions with zero backward-movement/lost-update. The identical TOCTOU shape inside the new `app.recalculate_shipment_tracking_health` itself (code-inferred, not independently live-reproduced by the reviewer) was fixed the same way, per-shipment.
5. `accuracy_meters` is honestly sourced from `app.canonical_telemetry_events.accuracy_meters` via the winning event, not fabricated — and a real, disclosed (not fixed — out of this write-path task's own scope) pre-existing gap was found: `app.ingest_direct_device_telemetry_batch`/`app.ingest_third_party_provider_webhook_event` both hardcode `p_accuracy_meters := null`, so this column is honestly null for any non-driver-mobile source today.
6. A same-signature `CREATE OR REPLACE FUNCTION` widens `app.arbitrate_and_project_vehicle_position` (never edits the applied migration file) to recompute tracking health for every shipment currently assigned the reporting vehicle (zero, one, or more than one — the loop does not assume exactly one). The first draft based this on the *original* pre-`ATW-226G` function body and would have silently reverted `ATW-226G`'s own geofence-detection widening; caught by a full `db:test` run, fixed by rebasing on the current body, disclosed in the migration header as a hard lesson.
7. `app.reconcile_shipment_tracking_health` — a bounded, cursor-paginated batch RPC for catching up any shipment whose health predates this migration.
8. Per `ERR-2026-004`: explicit `REVOKE`/`GRANT`; both new functions are `service_role`-only, matching the `detect_*`-family scan-function convention.

### Deliverable B — load/concurrency/recovery harness (closes `ISS-2026-014`)

1. New `scripts/load-tests/` directory, following `scripts/db-tests/run.sh`'s own conventions (extracted a shared `scripts/db-tests/lib/setup-disposable-db.sh` helper, reused by both harnesses — re-verified byte-for-byte identical `db:test` behavior before/after the extraction).
2. Eight real, live-executed scenarios: concurrent `post_inventory_movement` against a shared balance (empirically proving `ATW-015`'s own `SELECT ... FOR UPDATE` row-lock safety claim under real concurrent load for the first time); concurrent WMS pick/putaway task claiming; a 5,000-job backlog drain plus a deterministic dead-letter-and-replay scenario; GPS telemetry load reusing the *existing* Codec 8 Extended simulator (`services/gps-gateway/src/codec8e.ts`, `ATW-226D`) over real TCP sockets, including an outage/durable-buffer-recovery case added during the fix pass; `EXPLAIN (ANALYZE)` evidence for `ATW-023`'s own pagination indexes; an evidence-driven (and honestly inconclusive) investigation of `app.jobs`' claim-query index; a real client `SIGKILL` plus a genuine `pg_ctlcluster` cluster restart proving idempotent recovery; and a hybrid multi-source-arbitration concurrency scenario (added during the fix pass specifically to regression-prove the TOCTOU fix above) reaching 59,534 real concurrent transactions.
3. A disclosed, explicitly test-only job-polling script (`job-poll-worker.sh`) drives the soak portion of the job-queue scenario — **not** a production scheduler; `ISS-2026-015` (no live scheduler exists anywhere in this repository) remains open and untouched, exactly as that issue's own text anticipated.
4. **Two real bugs found and fixed in the harness itself, both caught by cross-checking computed numbers against independent sources rather than trusting a first-draft result:** a wrong pgbench log column produced nonsense latency percentiles (fixed, re-verified against pgbench's own summary stats); a per-file (not globally) sorted latency aggregation silently corrupted percentile lookups (fixed). A third, more serious bug was found during the fix pass: a bare `wait` in `run.sh` deadlocked against the script's own `tee`-based logging subshell under bash 5.2 — a genuine hang that meant no full run of the harness, as it stood, could ever have completed; live-reproduced in an isolated repro, fixed by capturing explicit PIDs and waiting on those.
5. **Judgment call, disclosed:** the task brief assumed the WMS pick/putaway claim RPCs use `SKIP LOCKED`; direct inspection showed both use blocking `FOR UPDATE`. Built a disclosed, test-only `SKIP LOCKED` candidate-selection wrapper around the real, unmodified claim RPCs rather than silently reinterpreting the task or fabricating a different production mechanism.
6. External-evidence policy: the GPS scenario measures the real TCP/protocol/decode layer against a fake (in-memory) ingest client, consistent with `ADR-0010` (no live Supabase project exists) and the identical pattern `services/gps-gateway/test/server.test.ts` already established — not a new crossing of the physical-hardware/live-provider boundary. Physical Teltonika hardware and a live third-party GPS provider remain `DEFERRED_EXTERNAL_HARDWARE_EVIDENCE`/`CONDITIONALLY_SKIPPED_PROVIDER_UNAVAILABLE` respectively, unchanged from every prior `ATW-226` checkpoint.
