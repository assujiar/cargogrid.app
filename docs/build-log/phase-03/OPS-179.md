## 3. Implementation

### 3.1 Scope boundaries and design decisions (disclosed, migration header)

One new permission action: the fixed 19-action `PLT-111` vocabulary includes `View margin` (already registered for `COM` at `COM-156`) — this migration registers the identical action for the `OPS` module, the same pattern `OPS-174` already used for `OPS:View cost`. `OPS:View margin` is deliberately its own bit, not reused from `OPS-178`'s own `OPS:View cost` — an actor may legitimately see one without the other, matching Commercial's own `COM:View cost`/`COM:View margin` orthogonality.

Revenue is read verbatim from the Job Order's own already-pinned `revenue_snapshot` (`totalAmount`/`currency`), never recomputed. Cost is the sum of every currently-approved `OPS-178` actual-cost version across every Shipment Order belonging to the Job Order. No FX conversion is performed — a currency mismatch (between cost versions, or between cost and revenue) makes the whole snapshot `unavailable` with a named `blocked_reason`, never a silently-wrong cross-currency subtraction.

Versioned snapshot, historical versions remain linked, never rewritten: `is_current`-exclusive; the first calculation for a job needs no reason, every subsequent recalculation while a current snapshot exists requires a non-empty `recalculation_reason`, mirroring `OPS-178`'s own adjustment-reason discipline. Explainability reuses `source_cost_version_ids` (the exact `app.shipment_actual_costs.id` array summed) rather than inventing a second read path — those rows are already independently readable by any caller who can see the snapshot. This is operational profitability, not accounting P&L — no GL/subledger/recognized-revenue table is touched.

### 3.2 Schema — `supabase/migrations/20260728120000_create_operations_job_profitability.sql`

`app.job_profitability_snapshots` (versioned, `unique` partial index on `is_current`). `app.has_view_job_margin` (thin wrapper over `app.evaluate_permission(..., 'OPS', 'View margin')`). `app.calculate_job_profitability` (`OPS:Edit` + `OPS:View margin` + record-scope gated; reads pinned revenue, sums approved costs, detects currency mismatch, computes `margin_amount`/`margin_percent`, versions the result). RLS-scoped base table plus `app.job_profitability_directory` (masks revenue/cost/margin amounts and `source_cost_version_ids` without `OPS:View margin`, mirroring `app.shipment_actual_costs_directory`'s own precedent).
