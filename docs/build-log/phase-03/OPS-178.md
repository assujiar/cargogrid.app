## 3. Implementation

### 3.1 Scope boundaries and design decisions (disclosed, migration header)

No new permission action is registered: `OPS-174` already registered `OPS:View cost`; `app.has_view_actual_cost` is this capability's own thin wrapper over the identical `app.evaluate_permission(..., 'OPS', 'View cost')` check, the same "one shared permission action, one wrapper function per consuming capability" precedent `COM-148`/`COM-156`/`OPS-174` already established. Writing cost data requires both `OPS:Edit` and `OPS:View cost`.

A cost component is either fully visible or fully hidden, never field-masked: every column of `app.shipment_actual_cost_components` is itself cost-shaped (rate, vendor, amount), so `authenticated` has no direct table access at all — the only read path, `app.list_actual_cost_components`, denies outright to an actor lacking `OPS:View cost`. The header's own `total_amount`/`estimated_amount` are masked (not the whole row) via `app.shipment_actual_costs_directory`, matching `app.job_orders_directory`'s own precedent.

Exact decimal arithmetic, never float: `numeric(14,4)` for quantity/rate, `numeric(14,2)` for every money column. `app.compute_actual_cost_component_amount` is the one place `greatest(quantity * rate, coalesce(minimum_charge, 0)) + surcharge` is computed and rounded (`round(..., 2)`).

Estimated cost is an optional, actor-supplied snapshot, never fabricated: no governed actual-cost estimate exists anywhere in this repository (Commercial's own vendor rate-selection detail was deliberately never copied onto the Job Order, per `00_OPERATIONS_WBS.md` §3's own field-mapping disclosure), so `estimated_amount` is recorded verbatim as whatever the draft's creator supplies; `app.evaluate_actual_cost_variance` returns `variance_available=false` rather than fabricating a linkage.

Versioned, adjustments preserve lineage: `app.create_actual_cost_adjustment` only starts from an `approved` version, copies its component lines onto a brand-new draft version, and flips the prior version's own `is_current` to false — never mutated or deleted. No Finance/AP/tax/journal/settlement scope is introduced.

### 3.2 Schema — `supabase/migrations/20260728110000_create_operations_actual_cost.sql`

`app.shipment_actual_costs` (versioned header, `draft -> submitted -> approved|rejected`, `unique` partial indexes for `is_current`/one-draft-at-a-time), `app.shipment_actual_cost_components` (line items with vendor/assignment/document lineage). Functions: `app.has_view_actual_cost`, `app.compute_actual_cost_component_amount`, `app.recalculate_actual_cost_total`, `app.create_actual_cost_draft`, `app.add_actual_cost_component` (vendor-required/assignment-mismatch/document-mismatch validated), `app.remove_actual_cost_component`, `app.submit_actual_cost` (requires ≥1 component), `app.decide_actual_cost` (reason mandatory on reject), `app.create_actual_cost_adjustment` (approved-only, reason mandatory, copies components), `app.evaluate_actual_cost_variance`, `app.list_actual_cost_components`. All authority-gated via `app.evaluate_permission(..., 'OPS', 'Create'|'Edit'|'View')` plus `app.has_view_actual_cost` plus `app.can_access_record` record-scope.
