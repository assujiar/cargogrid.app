## 3. Implementation

### 3.1 Scope boundaries and design decisions (disclosed, migration header)

A dedicated structured object, not a generic checklist item: `OPS-176`'s document checklist handles arbitrary named document types, while ePOD is a distinct object model with fixed fields (receiver name/position, signature file, photo files, geolocation, captured/server time). Both capabilities compose the same Platform Document/File Engine (`PLT-128`) underneath — `signature_file_id`/`photo_file_ids` reference `app.files.id` directly and re-read that row's own live `malware_scan_status`, never a second copy.

Versioned like `app.files` itself, never overwritten: a revision request always inserts a new row (`version_group_id` links the lineage, `version_number` increments, `is_latest_version` exclusive), and flips the prior row's own `is_latest_version` to false — full history remains, including the rejected version's own `review_notes`.

Geolocation reuses `PLT-134`'s own governed convention exactly (`app.geojson_point_to_geography`/`app.validate_geography_point`, `geography(Point,4326)`, RFC 7946 axis order) — this is the first domain table in the repository to add a real spatial column, proving out that migration's own disclosed forward seam.

Trustworthy server time is authoritative: `captured_at` is the field user's own claimed time; `server_received_at` (`default now()`) is what every downstream consumer must treat as authoritative.

Completion is a thin wrapper over `OPS-170`'s own already-shipped `delivered -> epod` transition — `app.complete_epod_capture` requires `status='approved'`, then calls `app.transition_shipment_order` internally with `evidence_ref` set to the capture's own id, never a second parallel status machine. Normal roles cannot rewrite completed evidence — every mutating function refuses once `status='completed'`; no correction path is built (RPD-022 Supreme Admin correction is a disclosed precedent elsewhere, not re-implemented here). Native mobile, offline capture/sync, and the customer-facing masked read are explicitly out of scope (RPD-004 online-first PWA only; a customer-visible projection is `OPS-180`'s own job).

### 3.2 Schema — `supabase/migrations/20260728100000_create_operations_epod_capture_review.sql`

`app.epod_captures` (versioned, `unique` partial index on `(version_group_id) where is_latest_version`, `gist` index on `delivery_geog`). Functions: `app.start_epod_capture` (requires `status='delivered'`, idempotent), `app.set_epod_evidence` (file tenant/record-mismatch validated, GeoJSON validated via the reused `PLT-134` convention, only mutates draft/revision_requested), `app.submit_epod_capture` (receiver + evidence + clean-scan gated), `app.review_epod_capture` (submitted -> approved/revision_requested, reason mandatory on revision), `app.revise_epod_capture` (revision_requested -> new draft version), `app.complete_epod_capture` (approved -> completed, wraps `app.transition_shipment_order`), `app.get_epod_capture_history` (full lineage read). All authority-gated via `app.evaluate_permission(..., 'OPS', 'Create'|'Edit'|'View')` plus `app.can_access_record` record-scope.

### 3.3 Service layer and UI

`server/contracts/epod-capture-review/epod-capture-review.ts(.test.ts)` (GeoJSON Point schema, relying on PostgREST's own automatic geography-to-GeoJSON serialization), `server/queries/epod-capture-review.ts(.test.ts)`, `server/mutations/epod-capture-review.ts(.test.ts)`.

## 8. Errors / recovery / risks / issues

Two real issues found and fixed during authoring, both confined to this checkpoint's own new files: (1) declaring a local `geography` variable inside a `SECURITY DEFINER` function whose own `set search_path = app, pg_temp` excludes `public` (where the PostGIS extension installs its types) raised `type "geography" does not exist` at parse/plan time (not merely a runtime issue) for every function that inserts/updates `app.epod_captures` — because Postgres re-validates every row-level `CHECK` constraint, including the `geography`-typed one, on every `INSERT`/`UPDATE` regardless of which columns changed, and constraint-expression compilation happens before any short-circuit evaluation; fixed by adding `public` to every such function's own `search_path`. (2) A vendor-resource-conflict fixture bug (reusing one vendor master record across both delivered Shipment Order fixtures tripped `OPS-172`'s own `assignment_conflict` rule); fixed with a second distinct vendor record. Zero Critical/High-severity issue remains open. Zero regression to any prior capability once both were corrected.
