## 3. Implementation

### 3.1 Design -- one shared posting service, closing FIN-202's own forward reference

`app.validate_finance_journal_line_balance` (at least two lines, exact nonzero debit=credit) is the one balance rule both the manual and system posting paths call -- never two competing checks. `app.create_finance_journal_draft` (manual: `FIN:Edit`, direct account references chosen by a human, validated active/postable/same-tenant) and `app.create_and_post_finance_system_journal` (system: called only from `FIN-202`'s own `app.post_finance_subledger_batch`) both call it before writing any row.

**Closes FIN-202's own disclosed forward reference**: this migration `CREATE OR REPLACE FUNCTION`s `app.post_finance_subledger_batch` (the established later-migration-extends-an-earlier-one's-function pattern) so that, immediately after writing its own subledger lines, it accumulates the identical already-resolved `(accountId, direction, amount)` lines and calls `app.create_and_post_finance_system_journal` with them, then sets the batch's own `gl_journal_id`. One posted journal per posted subledger batch, mirroring its lines exactly, never a second.

**Manual journal lifecycle**: `draft -> submitted -> approved -> posted` (mirrors `FIN-197`/`FIN-200`'s own shape); `approve`/`post` share `FIN:Approve` since this checkpoint has no separate treasury/GL-poster role, the identical disclosed bound `FIN-201`'s own settlement `execute`/`post` recorded. A system journal skips straight to `posted` at creation -- its own source event was already authority-checked upstream, never a silent bypass of the manual path's own controls.

**Reversal is explicitly out of scope** (Prompt 203 section 32: "reverse posted journal via FIN-206") -- no reversal function exists here.

### 3.2 Schema — `supabase/migrations/20260729170000_create_finance_journal.sql`

`app.finance_journals` (idempotent unique on `tenant_id, idempotency_key`; a partial unique on `tenant_id, source_type, source_id` for system journals; `total_amount` the balanced debit/credit total), `app.finance_journal_lines` (one exact debit/credit line; `dimension` a free-form jsonb tag, bounded scope disclosed -- not yet validated against FIN-191's own `finance_dimensions` catalogue), `app.finance_journal_number_counters` (mirrors `FIN-200`'s own counter table exactly, shared by both posting paths). Functions: `app.check_finance_journal_authority`, `app.validate_finance_journal_line_balance`, `app.create_finance_journal_draft`, `app.submit_finance_journal_for_approval`, `app.discard_finance_journal_draft` (draft/submitted only), `app.approve_finance_journal`, `app.post_finance_journal` (idempotent, re-validates the stored lines' own balance, period-aware, assigns `journal_number`), `app.create_and_post_finance_system_journal` (idempotent on source, posts immediately), `app.list_finance_journals`, `app.get_finance_journal_lines`.
